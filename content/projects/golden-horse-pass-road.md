## 프로젝트 핵심 스택

황금마패의 길은 관람객의 휴대전화에서 장소 탐색과 이야기 감상, 현장 QR 진입, AR 사진 촬영, 마패 조각 수집을 연결한 Nuxt 기반 관람 콘텐츠입니다. 한국어와 영어 콘텐츠를 같은 화면 구조에 연결하고, 촬영 결과와 스탬프 상태는 관람객의 기기 안에 보관하도록 구성되어 있습니다.

- 다국어 콘텐츠: Nuxt Content와 Nuxt i18n 기반 한국어·영어 도슨트
- 현장 진입: 브라우저 카메라와 `jsQR`를 이용한 QR 경로 검증
- AR 촬영: Canvas 기반 카메라·캐릭터 영상·배경 합성
- 로컬 갤러리: IndexedDB 원본·썸네일 저장과 Web Share API 연동
- 관람 진행 상태: Pinia와 브라우저 로컬 저장소 기반 마패 조각 기록
- 배포 형태: Nuxt 정적 생성과 언어별 도슨트 경로 프리렌더

## 배경과 해결하려던 문제

소스에서 확인되는 목표는 관람객이 별도 앱 설치 없이 모바일 브라우저에서 `황금마패의 길` 이야기를 따라가도록 만드는 것입니다. 홈과 여정 지도에서 전체 맥락을 파악하고, 여덟 개 구역의 도슨트를 순서대로 듣거나 현장의 QR을 통해 해당 장소의 이야기로 진입할 수 있습니다.

여기에 설명을 읽고 듣는 경험만 두지 않고, 특정 구역의 AR 촬영과 다섯 개 마패 조각 수집을 연결했습니다. 따라서 콘텐츠 탐색, 카메라 권한, 촬영 결과 보관, 재방문 시 진행 상태 유지가 하나의 모바일 사용자 흐름 안에서 함께 동작해야 했습니다.

## 담당 범위

개인 프로젝트로 전체 개발을 담당했습니다. 세부 기능 기획안과 UI 레이아웃 결정에 참여했고, 구현 방식에 대한 기술 자문도 맡았습니다.

저장소에서 확인되는 구현 범위는 다음과 같습니다.

- Nuxt Content를 사용한 한국어·영어 도슨트 콘텐츠와 페이지 구성
- 홈, 지도, 이야기 목록, 구역별 도슨트, QR, AR, 갤러리, 스탬프 화면 연결
- 브라우저 카메라를 사용하는 QR 인식과 AR 촬영 흐름
- Canvas 기반 카메라 이미지·캐릭터 영상·배경 합성
- IndexedDB 사진 보관과 Pinia 기반 스탬프 상태 유지
- 모바일 하단 내비게이션과 언어별 경로 처리

## 시스템 흐름

이 프로젝트의 구조는 기술 계층보다 관람객의 이동 순서로 이해하는 편이 적합합니다.

1. 한국어 또는 영어를 선택합니다.
2. 여정 지도와 여덟 개 구역 목록에서 이야기를 탐색합니다.
3. 스탬프 화면에서 카메라를 열어 현장 QR을 스캔합니다.
4. QR에 연결된 구역에서 텍스트·이미지와 같은 언어의 오디오 도슨트를 감상합니다.
5. 지정된 구역에서는 AR 촬영 화면으로 이동해 카메라 영상과 캐릭터를 합성합니다.
6. 합성 결과는 브라우저의 IndexedDB 갤러리에 보관하며 공유, 다운로드와 삭제를 지원합니다.
7. 이야기 목록이 아니라 현장 QR을 거쳐 특정 구역에 진입했을 때 해당 마패 조각을 기기 내 진행 상태에 반영합니다.

상단 다이어그램은 관람객, 언어 라우터, 다국어 도슨트, QR 스캐너, 스탬프 저장소, AR 합성과 IndexedDB 갤러리 사이에서 요청과 결과가 전달되는 순서를 보여줍니다. 스탬프와 AR은 하나의 구역에서 연속 실행되는 단계가 아니라, 도슨트 구역에 따라 나뉘는 현장 경험입니다.

## 핵심 구현

### 1. 콘텐츠와 경로를 함께 묶은 다국어 도슨트

한국어와 영어 콘텐츠를 Nuxt Content 컬렉션으로 분리하고, 홈·지도·목록·스탬프와 구역별 도슨트가 현재 언어에 맞는 문서를 조회합니다. 선택한 언어는 브라우저에 보관하고, 첫 방문 시 저장된 값에 맞는 언어 경로로 이동합니다. 도슨트 오디오도 언어와 구역 번호를 기준으로 선택해 텍스트와 음성의 맥락을 맞춥니다.

### 2. 현장 진입 경로를 구분하는 QR 경험

QR 화면은 후면 카메라를 우선 요청하고, 영상 중앙 영역을 주기적으로 샘플링해 `jsQR`로 해석합니다. 인식 결과는 서비스에서 허용한 호스트인지 확인한 뒤 경로와 쿼리만 내부 라우터에 전달합니다. 목록에서 직접 연 도슨트와 현장 QR로 진입한 도슨트를 구분해, 단순 열람이 스탬프 획득으로 이어지지 않도록 했습니다.

### 3. 브라우저 안에서 완결되는 AR 사진과 갤러리

AR 화면은 전·후면 카메라 전환을 지원하고, 카메라 캡처와 투명 배경 캐릭터 영상을 세로형 Canvas에 합성합니다. 생성한 PNG와 축소 썸네일은 IndexedDB에 저장하며, 오래된 결과부터 정리해 최대 25개를 유지합니다. 갤러리에서는 최신 사진부터 확인하고 Web Share API가 지원되면 파일 공유를, 지원하지 않으면 다운로드를 제공하며 개별 삭제도 할 수 있습니다.

### 4. 재방문을 고려한 마패 조각 상태

다섯 개 마패 조각은 Pinia 스토어와 브라우저 로컬 저장소에 유지됩니다. 특정 도슨트 구역을 현장 흐름으로 방문하면 대응하는 조각을 획득하고 팝업으로 결과를 알립니다. 저장 상태에는 갱신 시각과 초기화 예정 시각을 함께 두어 일정 기간이 지난 관람 기록을 초기화합니다.

## 기술 선택과 트레이드오프

- `Nuxt Content`는 언어와 구역별 원고를 Vue 화면 코드에서 분리하고 정적 생성 대상에 포함하기 적합합니다. 다만 콘텐츠 변경과 화면 동작을 함께 검증하는 운영 절차는 추가 확인이 필요합니다.
- `jsQR`와 Canvas를 사용하면 QR 이미지를 외부 분석 서비스로 전송하지 않고 브라우저에서 처리할 수 있습니다. 대신 카메라 권한과 기기별 영상 성능에 영향을 받으므로 요청 조건이 맞지 않을 때 기본 카메라로 재시도하는 흐름을 두었습니다.
- `IndexedDB`는 합성 사진 Blob을 서버 업로드 없이 기기에 저장할 수 있습니다. 기기·브라우저별 저장 한계와 데이터 삭제 가능성을 고려해 사진 수를 제한하고 썸네일을 별도로 생성했습니다.
- `localStorage` 기반 스탬프는 계정 없이 곧바로 체험할 수 있지만 다른 기기나 브라우저 사이에서 진행 상태를 동기화하지는 않습니다.

## 테스트·배포·운영 안정성

Vitest, Nuxt Test Utils와 Vue Test Utils가 설정되어 있으며, 로컬 저장소 기반 스탬프 상태의 초기값·변경·초기화·복구를 확인하는 테스트가 있습니다. 현재 활성화된 Pinia 스탬프 스토어와 QR·AR·IndexedDB 흐름 전체에 대한 테스트 범위 및 실제 통과 여부는 추가 확인이 필요합니다.

Nuxt 정적 생성 스크립트와 한국어·영어의 여덟 개 도슨트 경로에 대한 프리렌더 설정이 확인됩니다. 카메라 스트림은 화면을 벗어날 때 정리하고, 요청한 촬영 조건을 적용할 수 없으면 기본 카메라로 다시 요청합니다. QR은 허용된 서비스 호스트만 받아들이며, 촬영 사진은 서버로 보내는 코드 없이 브라우저 저장소에서 관리됩니다.

현재 서비스 중이며 프로젝트명과 화면을 모두 공개할 수 있습니다. 영상이 포함된 최초 페이지의 측정 로드 시간은 450ms입니다. 지원 기기 범위와 네트워크가 불안정한 현장에서의 장기 검증 결과는 별도로 확인할 항목입니다.

## 의사결정과 결과

### 문제

웹 앱에서 촬영한 AR 합성 사진을 임시로 보관하고, 관람객이 갤러리처럼 다시 확인할 수 있어야 했습니다. 사진을 서버로 전송하면 네트워크 트래픽과 저장 비용뿐 아니라 관람객 이미지의 개인정보 처리 범위도 커집니다.

### 대안 소개

- 촬영 결과를 CDN에 업로드하고 서버 갤러리에 추가하는 방식
- 브라우저 자체 저장소를 활용해 관람객 기기 안에서 보관하는 방식

### 결정 이유

IndexedDB를 이용한 기기 내 저장을 선택했습니다. 이미지 업로드 트래픽과 CDN 비용을 없애고 외부 서비스 의존성을 줄이는 동시에, 관람객의 촬영 사진이 서버로 전송되지 않도록 해 개인정보 보호 범위를 단순화할 수 있기 때문입니다.

### 결과

CDN 비용과 외부 저장 서비스 의존성 없이 최대 25장의 촬영 결과와 썸네일을 기기 안에서 관리할 수 있게 했습니다. 갤러리 로딩은 1초 미만이며, 영상이 포함된 최초 페이지도 450ms에 로드됩니다.

프로젝트명과 실제 화면은 공개 가능하며, 이미지 자료는 준비되는 대로 추가할 예정입니다.
