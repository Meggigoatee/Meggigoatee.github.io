## 프로젝트 목적

B the B LIVE WALL은 지정한 소셜 미디어 해시태그의 최신 게시물을 수집해 대형 전시 화면에 포토 카드 형태로 보여주는 Electron 애플리케이션입니다. 여러 해시태그에서 들어온 게시물을 하나의 흐름으로 합치고, 새로운 콘텐츠가 도착하면 화면 전체를 다시 그리지 않고 기존 카드 중 하나를 애니메이션과 함께 교체합니다.

전시 화면은 고정된 그래픽을 재생하는 데 그치지 않고, 게시물 갱신과 카드 순환, 누적·당일 집계 표시, 현장 레이아웃 조정까지 한 앱에서 처리하도록 구성되어 있습니다.

## 담당 범위

본인의 정확한 담당 범위, 팀 구성, 작업 기간과 기획·디자인 참여 여부는 확인이 필요합니다.

저장소에서 확인되는 구현 범위는 다음과 같습니다. 이 목록이 개인 기여 범위와 동일하다고 단정하지 않습니다.

- Electron 메인·프리로드·Vue 렌더러로 나눈 데스크탑 애플리케이션 구조
- 외부 API를 이용한 해시태그별 최신 게시물 수집과 응답 정규화
- 여러 해시태그의 게시물 병합, 중복 제거와 증분 갱신
- 카드 슬롯 순환, 진입·퇴장·흔들림 애니메이션과 집계 표시
- 카드·패널 위치 편집, 노출 제어와 카드 내부 영역 캘리브레이션
- Electron Store 기반 현장 설정 유지와 Electron Forge 패키징
- 수집 로직, 포토월 유틸리티와 Vue 컴포넌트의 Vitest 테스트

## 기술 스택

- 데스크탑 런타임과 패키징: Electron, Electron Forge, Vite
- 화면 구성: Vue 3 Composition API, TypeScript, Pinia
- 외부 연동: Axios, Electron IPC와 Context Bridge
- 로컬 설정과 자원: Electron Store, Electron 커스텀 프로토콜
- 테스트: Vitest, Vue Test Utils, Happy DOM

## 핵심 구현

### 1. 여러 해시태그의 증분 수집과 응답 정규화

외부 API 요청은 Electron 메인 프로세스에서 수행하고, 렌더러는 프리로드에서 노출한 제한된 인터페이스만 호출합니다. API 인증 정보와 연결 설정을 화면 코드에서 분리한 구조입니다. 페이지 단위 응답에서는 게시물 ID를 기준으로 중복을 제거하고, 알려진 ID가 나타난 뒤에도 같은 응답 안의 신규 항목을 끝까지 검사한 다음 최신 순으로 정렬합니다.

여러 해시태그는 각각 수집한 뒤 결과를 합칩니다. 한 해시태그의 요청이 실패해도 다른 결과를 처리할 수 있도록 요청별 성공과 실패를 나누며, 실제 화면에 필요한 수보다 과도하게 수집하지 않도록 현재 보이는 카드 수를 요청 상한에 반영합니다.

### 2. 중복 없는 교체 큐와 고정 슬롯 순환

초기 게시물과 새로 수집한 게시물을 ID 기준으로 합치고, 이미 화면에 있거나 교체 대기 중인 항목은 큐에 다시 넣지 않습니다. 해시태그마다 최근에 확인한 ID 목록을 제한된 크기로 보관해 다음 갱신 요청에 사용합니다. 같은 게시물이 여러 해시태그 결과에 포함돼도 화면에서는 한 번만 다룹니다.

카드 슬롯 순서는 앱이 시작할 때 한 번 섞은 뒤 반복합니다. 새로운 게시물은 오래된 항목부터 큐에 넣고, 설정된 간격마다 다음으로 보이는 슬롯을 찾아 퇴장·진입 애니메이션으로 교체합니다. 숨긴 슬롯은 순서를 깨뜨리지 않고 건너뛰며, 모든 슬롯이 숨겨진 경우에는 콘텐츠를 잘못 소비하지 않도록 대기 상태를 유지합니다.

### 3. 전시 화면에 맞춘 레이아웃 편집과 캘리브레이션

포토월은 초광폭 기준 캔버스를 창 크기에 맞춰 같은 비율로 축소합니다. 카드, 안내 패널과 집계 패널은 현장에서 편집 모드를 켜고 드래그해 위치를 바꿀 수 있으며, 필요 없는 카드는 숨겼다가 다시 활성화할 수 있습니다.

카드 내부의 사진, 캡션과 메타 영역도 별도 캘리브레이션 화면에서 이동하고 크기를 조절할 수 있습니다. 편집을 마치면 요소별 위치, 회전, 노출 상태와 카드 템플릿을 Electron Store에 저장해 다음 실행에서도 유지합니다. 고정된 디자인 자산과 실제 디스플레이 배치의 차이를 다시 빌드하지 않고 조정하기 위한 운영 기능입니다.

### 4. Electron 경계 안의 외부 이미지와 로컬 자원 처리

원격 이미지 제공처가 요구하는 요청 헤더는 Electron 세션에서 보완하고, 렌더러의 이미지 로드가 실패하면 제한된 횟수만 재시도한 뒤 해당 이미지를 숨깁니다. 수집 주기와 카드 교체 애니메이션은 서로 다른 타이머로 운용하며, 갱신 중에는 다음 갱신이 겹치지 않도록 상태를 잠급니다. 컴포넌트가 종료될 때 등록한 타이머와 이벤트 리스너도 정리합니다.

배경과 카드 프레임 같은 현장 자원은 패키지 외부 리소스로 포함하고 Electron 커스텀 프로토콜로 읽습니다. 프로토콜 처리 단계에서 허용된 자원 영역을 벗어나는 경로를 거부해, 운영자가 교체 가능한 에셋과 애플리케이션 코드의 경계를 유지합니다.

## 핵심 판단과 결과

코드에서 확인되는 결과는 여러 해시태그의 최신 게시물을 주기적으로 합치고, 중복 없이 제한된 카드 슬롯에 순차 반영하는 포토월 화면입니다. 수집 실패를 해시태그별로 분리하고, 신규 항목이 없을 때는 기존 화면을 유지하며, 현장에서 레이아웃과 카드 템플릿을 직접 조정할 수 있도록 구성한 점이 특징입니다.

Vitest 테스트는 페이지형 수집 결과와 기존 ID 처리, 중복 제거와 슬롯 순환, 날짜 기준 집계, 카드 생성·갱신·편집, 컴포넌트 종료 시 자원 정리를 다룹니다. 현재 콘텐츠 작성 과정에서는 테스트 통과 여부와 패키지 실행을 새로 검증하지 않았습니다.

실제 운영·납품 상태, 공개 가능한 화면, 외부 서비스 이용 정책, 장기간 갱신 안정성과 관람객 반응은 확인이 필요합니다. 대표 기술 판단은 `문제 → 대안 소개 → 결정 이유 → 결과` 순서로 추가 확인합니다.

- 지원 디스플레이 환경과 실제 운영 기간
