## 프로젝트 목적

정읍 방문자센터 마을 만들기는 카메라로 감지한 물리 오브젝트의 위치를 디지털 마을 풍경에 반영하는 Electron 기반 전시 프로그램입니다. 오브젝트는 도로, 철로, 강, 하늘길의 네 종류로 분류되며, 같은 종류의 지점을 연결해 길을 만들고 차량·열차·보트·비행기와 주변 장식이 나타나도록 구성되어 있습니다.

관람객이 오브젝트를 놓고 치우는 동작은 감지 좌표의 생성·삭제 이벤트가 되고, 렌더러는 변화한 노드와 경로를 반응형으로 다시 그립니다. 고정된 영상을 재생하는 대신 물리 배치에 따라 마을 장면이 달라지는 체험을 목표로 한 구조입니다.

## 담당 범위

본인의 정확한 담당 범위, 작업 기간, 팀 구성과 기획·디자인 참여 여부는 확인이 필요합니다.

저장소에서 확인되는 구현 범위는 다음과 같습니다.

- 카메라 기반 오브젝트 감지 프로세스와 Electron 메인 프로세스 연동
- 다중 카메라 좌표 보정, 오브젝트 생성·유실 추적과 렌더러 IPC 전달
- PixiJS 기반 배경, 경로, 장식, 교량, 교통수단과 동물 레이어 구성
- 노드 간 연결, 교차점 판정과 장식 충돌 회피를 포함한 배치 로직
- 베지어 경로 후보 생성과 장애물 충돌 판정 모듈
- 전시 화면용 전체 화면 실행과 Windows 설치 패키징

## 기술 스택

- 데스크탑 애플리케이션: Electron, Vue 3, TypeScript, Pinia
- 실시간 장면 렌더링: PixiJS 8, 비디오·이미지 텍스처, Ticker
- 경로 계산: Prim 최소 신장 트리, Bezier.js
- 감지 연동: Python 보조 프로세스, Electron IPC
- 검증과 배포: Vitest, electron-vite, electron-builder

## 핵심 구현

### 1. 감지 결과를 안정적인 마을 노드로 변환

Python 감지 프로세스가 카메라별 오브젝트 종류와 중심 좌표를 JSON 스트림으로 전달합니다. Electron 메인 프로세스는 카메라별 추적기를 두고 같은 종류와 가까운 좌표를 연속 프레임에서 매칭합니다. 일정 횟수 이상 안정적으로 감지된 경우에만 고정 좌표와 ID를 부여하고, 일정 횟수 동안 보이지 않을 때 삭제 이벤트를 내보내 순간적인 검출 흔들림이 바로 화면 변화로 이어지지 않도록 했습니다.

다중 카메라 입력은 카메라별 유효 범위를 통과한 값만 사용하고, X 오프셋과 화면 중심으로부터의 거리에 따른 Y 보정을 적용합니다. 생성·삭제 이벤트는 IPC를 통해 렌더러의 Pinia 스토어에 반영되며 도로, 철로, 강, 하늘길 노드가 각각 관리됩니다.

### 2. PixiJS 레이어와 반응형 경로 장면

PixiJS 애플리케이션은 1920×1200 디자인 좌표계를 기준으로 배경 비디오와 월드 컨테이너를 만들고, 실제 창 크기에는 레터박스 방식으로 맞춥니다. 각 경로 종류는 길, 장식, 교통수단, 교량과 노드 레이어를 분리해 쌓으며, 노드나 간선이 바뀌면 해당 레이어와 교통 흐름을 다시 구성합니다.

같은 종류의 노드는 Prim 최소 신장 트리로 연결해 모든 지점을 불필요하게 전부 잇지 않고 하나의 연결된 경로를 만듭니다. 경로는 타일 텍스처로 표현하며 강과 하늘길에는 텍스처 흐름을, 노드에는 종류별 영상 효과를 적용합니다.

### 3. 교차·충돌을 고려한 배치 규칙

도로·철로·강의 선분 교차를 계산해 도로가 강이나 철로와 만나는 위치, 철로가 강과 만나는 위치에 종류별 교량을 배치합니다. 길 주변의 건물, 나무와 꽃 장식은 일정 간격으로 후보 위치를 만들되, 다른 경로의 폭과 여백 안에 들어가거나 노드 주변을 침범하면 제외합니다. 교차점 인근도 비워 교량과 장식이 겹치지 않도록 합니다.

동물 레이어는 화면 경계와 다른 동물의 반경을 확인해 회전 방향을 바꾸고, 일정 시간이 지나면 페이드아웃 후 새 배치로 교체합니다. 이 배치 규칙은 장면 안에서 길, 장식과 움직이는 오브젝트가 서로 덮여 보이는 상황을 줄이는 역할을 합니다.

### 4. 경로 이동과 베지어 확장 구현

현재 PixiWorld의 차량·열차·보트·비행기는 각 MST 선분을 따라 위치를 선형 보간하고, 경로 각도와 이동 방향에 맞춰 스프라이트를 회전시킵니다. 종류별 속도, 간격과 차선 오프셋을 적용하고 노드 변경 시 기존 이동체와 생성기를 새 경로에 맞게 동기화합니다.

별도 경로 모듈에는 두 지점의 거리에 따라 2차 또는 3차 베지어를 만들고, 곡률의 방향과 크기가 다른 후보를 생성하는 로직이 있습니다. 곡선을 일정 간격으로 샘플링해 원형 장애물과 도로 폭을 포함한 여유 거리 안에서 충돌하는지도 판정합니다. 다만 조사한 현재 PixiWorld 렌더링에서는 이 베지어·원형 충돌 모듈을 호출하지 않고 직선 경로를 사용하므로, 베지어 이동은 적용 완료 기능이 아니라 구현된 확장 후보로 구분했습니다.

## 핵심 판단과 결과

소스에서 확인되는 결과는 실시간 감지 좌표가 노드와 경로로 변환되고, 그 변화에 맞춰 PixiJS 마을의 길·교량·장식·교통수단이 재구성되는 전시용 데스크탑 애플리케이션입니다. 입력 안정화, 그래프 연결, 시각 레이어와 움직임을 분리해 물리 배치 변화가 전체 장면으로 이어지도록 만든 점이 특징입니다.

Vitest에는 오브젝트 생성·유실 추적, 카메라 좌표 보정, 최소 신장 트리와 Pinia 노드 스토어 테스트가 있습니다. 실제 테스트 통과 여부는 이번 읽기 전용 조사에서 확인하지 않았습니다. Windows NSIS 설치 패키지 설정과 전체 화면·항상 위 실행 구성이 확인되지만, 실제 납품·운영 상태, 현장 장비 구성과 정량 성과는 추가 확인이 필요합니다. 대표 기술 판단은 `문제 → 대안 소개 → 결정 이유 → 결과` 순서로 추가 확인합니다.
