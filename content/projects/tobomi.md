## 프로젝트 핵심 스택

Tobomi는 일상적인 작업 관리를 돕는 생산성 기능과 화면 위에서 반응하는 애니메이션 컴패니언 "마루"를 결합한 개인 데스크탑 애플리케이션입니다. 메모·캘린더·타이머·집중 흐름과 컴패니언의 빠른 실행·상태 반응을 하나의 로컬 애플리케이션 안에서 연결했습니다. 2026년 9월 7일 Windows 데모를 공개했고, 2026년 9월 21일 캘린더를 추가한 v0.6.0 베타를 [공식 사이트](https://tobomi.app)에서 배포하고 있습니다.

- 사용자 인터페이스: Vue 3 Composition API와 Pinia
- 데스크탑 런타임: Tauri 2와 Rust
- 로컬 데이터: SQLx와 SQLite
- 생산성 기능: 블록형 메모, 자체 캘린더, 이름을 붙여 여러 개 실행하는 타이머, 목표 기반 집중·휴식
- 컴패니언: 작업 이벤트와 직접 상호작용에 반응하는 레이어 애니메이션
- 운영체제 연동: 시스템 트레이, 단일 인스턴스, 로그인 시 자동 실행, 선택적 시스템 활동 감지
- 사용자 환경: 한국어·영어·일본어·중국어 간체와 시스템·밝은·다크 테마 전환
- 배포와 갱신: 공식 사이트의 Windows 데모 다운로드와 앱 안에서 확인하는 자동 업데이트

## 배경과 해결하려던 문제

개인 생산성 도구는 기능을 제공하는 것만으로는 사용자의 현재 작업 맥락과 자연스럽게 이어지기 어렵습니다. Tobomi는 메모와 시간 관리 기능을 독립된 도구로 나열하는 대신, 항상 화면에 머무는 컴패니언을 주요 진입점이자 피드백 채널로 사용하는 방향을 탐색합니다.

이를 위해 다음 문제를 함께 다룹니다.

- 기능별 창이 여러 개 열려도 데이터와 실행 상태가 일관되게 유지될 것
- 웹 UI가 로컬 데이터베이스와 운영체제 기능에 직접 결합되지 않을 것
- 메모 저장, 타이머·집중 상태 변화가 컴패니언 반응으로 자연스럽게 이어질 것
- 앱을 닫거나 다시 실행하는 과정에서 편집 중인 데이터와 실행 상태를 안전하게 정리할 것
- 시스템 활동은 사용자가 동의한 범위에서만 감지하고 입력 내용은 다루지 않을 것
- 일정은 외부 계정 없이 이 기기에 저장하면서도 시간대와 반복 규칙을 정확히 다룰 것
- 데모 사용자가 설치 파일을 다시 찾지 않고도 새 버전을 받을 수 있을 것

## 담당 범위

개인 프로젝트로 기획, UI·캐릭터 디자인과 전체 개발을 담당하고 있습니다. 구현 범위는 Vue 기반 다중 창 UI, Pinia 상태 관리, Tauri 커맨드 경계, Rust 도메인 서비스, SQLx·SQLite 저장 계층, 컴패니언 상태 머신과 레이어 애니메이션, 트레이·자동 실행·단일 인스턴스·시스템 활동 연동, 4개 언어 번역 카탈로그와 테마, 로컬 캘린더의 반복·시간대 계산, 서명 검증을 포함한 자동 업데이트입니다.

앱과 별도로 공개 랜딩 페이지 [tobomi.app](https://tobomi.app)도 직접 기획·개발해 운영합니다. Vue 3와 Vite로 만들고 4개 언어를 정적 프리렌더하며, Cloudflare Workers에 배포해 설치 파일 제공과 업데이트 피드, 사용 후 설문 연결과 다운로드 요청 집계를 담당합니다.

## 시스템 흐름

Vue 컴포넌트는 네이티브 기능이나 SQL을 직접 다루지 않습니다. 기능별 서비스가 타입이 지정된 Tauri 커맨드를 호출하고, Rust 계층이 검증·비즈니스 규칙·데이터 저장과 운영체제 연동을 담당합니다. 변경 결과는 반환값과 애플리케이션 이벤트로 각 창의 Pinia 상태에 다시 반영됩니다.
상단 시퀀스 다이어그램은 UI 요청이 Tauri Commands와 Rust Services를 지나 로컬 데이터 또는 운영체제 기능을 처리하고, 완료 이벤트가 각 창의 상태로 돌아오는 순서를 보여줍니다. 이어지는 유스케이스 다이어그램은 사용자와 Windows, 배포 서버를 외부 액터로 두고 메모, 일정, 타이머, 집중, 컴패니언과 데스크탑 연동·업데이트 기능의 사용 범위를 구분합니다.

## 핵심 구현

### 1. Rust 커맨드로 통일한 로컬 데이터 경계

프론트엔드는 SQL 문자열을 갖지 않고 모든 데이터 읽기와 쓰기를 `invoke` 기반 서비스로 요청합니다. Tauri 커맨드는 입력과 상태를 확인한 뒤 Rust 도메인 로직에 처리를 위임하고, SQLx가 관리하는 SQLite 풀과 트랜잭션을 사용합니다.

이 구조는 메모의 블록·체크리스트처럼 여러 테이블을 한 번에 갱신하는 작업을 하나의 트랜잭션으로 묶고, 프론트와 저장소 사이의 타입 계약을 Rust 모델로 집중시킵니다. 앱 시작 시 데이터베이스 파일과 풀을 준비하고 내장된 마이그레이션을 적용하며, 외래 키 제약도 연결 옵션에서 활성화합니다.

### 2. 다중 창 상태와 의미 이벤트 동기화

대시보드, 메모, 캘린더, 타이머, 집중과 컴패니언은 각각 별도 창으로 동작합니다. 각 창은 독립된 웹뷰와 Pinia 인스턴스를 가지므로 메모리 상태를 직접 공유하지 않습니다. 대신 Rust의 쓰기가 완료되면 `memo:changed`, `timer:changed`, `focus:changed` 같은 의미 이벤트를 전체 창에 전달하고, 각 스토어가 필요한 데이터를 다시 읽어 자신의 상태를 갱신합니다.

기능 창은 숨겨진 상태로 생성한 뒤 데이터와 위치가 준비된 시점에 스스로 표시합니다. 저장된 창 위치가 적용되기 전에 기본 위치가 잠깐 보이는 현상을 줄이기 위한 수명 주기입니다. 이미 열린 창은 새로 만들지 않고 복원해 포커스하며, 대시보드의 닫기 동작은 앱 종료가 아니라 숨김으로 처리합니다.

### 3. 생산성 이벤트를 컴패니언 행동으로 변환

컴패니언은 메모 입력·저장, 체크 항목 완료, 집중 시작·일시정지·완료 같은 이벤트를 구독합니다. 원본 이벤트를 애니메이션 프레임에 바로 연결하지 않고, 정규화된 반응 요청을 Pinia 상태 머신에 전달한 뒤 우선순위와 현재 모드에 맞는 행동을 선택합니다.

상태 머신은 작업 중·집중·휴식 같은 지속 상태와 클릭·완료 같은 일시 반응을 분리합니다. 높은 우선순위 반응은 진행 중인 낮은 우선순위 반응을 대체하고, 반응이 끝나면 이전 작업 상태로 복귀합니다. 선택된 행동은 manifest에 정의된 스프라이트 시트의 프레임 재생으로 표현되며, 캐릭터 클릭·더블클릭·쓰다듬기·드래그와 커서 접근도 같은 반응 경계로 정리됩니다.

### 4. 데스크탑 수명 주기와 선택적 시스템 연동

Rust가 시스템 트레이를 소유하고 대시보드·컴패니언 표시, 숨김과 종료 흐름을 조정합니다. 단일 인스턴스 플러그인은 같은 로컬 데이터베이스를 여러 프로세스가 동시에 사용하는 상황을 막고, 두 번째 실행 요청이 오면 기존 컴패니언을 다시 표시합니다. 자동 실행 상태는 애플리케이션 설정에 복제하지 않고 운영체제에 등록된 실제 상태를 조회합니다.

시스템 활동 감지는 기본적으로 꺼져 있으며 자리 비움·잠금과 외부 타이핑 여부를 종류별 동의 후에만 사용합니다. 입력 내용, 키 종류, 창 제목이나 화면은 수집하지 않고 정제된 상태 변화만 컴패니언에 전달합니다. 동의를 철회하면 감지를 중지하고 관련 로컬 집계도 초기화하는 흐름을 둡니다.

### 5. 계정 없이 동작하는 로컬 캘린더

v0.6.0 베타에서 자체 캘린더를 추가했습니다. 월·주·일·일정 목록 보기와 종일·여러 날·반복 일정, 캘린더별 분류색과 표시 토글, 검색, 드래그로 만들고 옮기고 길이를 조절하는 편집, 일정 복제와 삭제 실행 취소를 지원합니다. 외부 계정 연동 없이 모든 일정을 기기의 SQLite에 저장합니다.

반복 계산과 검증은 Rust가 소유합니다. 반복은 회차를 모두 복제하지 않고 규칙과 회차별 예외로 저장하며, 이번 회차만 바꿀 때는 원래 시작값을 키로 보존해 다른 날짜로 옮긴 뒤에도 원본 회차를 식별합니다. 날짜와 시간대 연산에는 chrono·chrono-tz를 사용해 서머타임으로 사라진 시각은 건너뛰고 중복되는 현지 시각은 먼저 오는 시각으로 해석합니다.

동시 편집과 되돌리기에도 계약을 두었습니다. 일정 수정은 revision 비교로 충돌을 감지해 오래된 편집 내용이 새 데이터를 덮어쓰지 않게 하고, 삭제는 논리 삭제와 일회성 복구 토큰으로 실행 취소를 지원합니다. 늦게 도착한 이전 날짜 조회가 최신 화면을 덮어쓰지 않도록 요청 순서도 확인합니다.

### 6. 데모 배포와 사용자가 결정하는 자동 업데이트

데모 사용자가 설치 파일을 다시 찾지 않도록 Windows x64 NSIS 자동 업데이트를 넣었습니다. 확인 주소는 랜딩 HTML과 분리한 정적 JSON 피드로 고정하고, 설치 파일도 같은 사이트의 정적 자산으로 제공합니다. 시작 30초 후와 이후 24시간 간격으로 확인하지만 다운로드와 설치는 사용자가 직접 선택하며, 개발 빌드는 자동으로 확인하지 않습니다.

Rust가 업데이트 후보와 검증된 바이트, 작업 잠금과 상태 revision을 소유하고 Vue는 표시와 선택만 맡습니다. 여러 창이 각자 확인하거나 늦은 응답이 최신 상태를 덮어쓰는 문제를 막기 위한 구조입니다. 설치 직전에 피드를 다시 확인해 버전·URL·서명이 달라지면 설치하지 않고, 진행 중인 타이머나 집중이 있으면 설치를 막습니다. 업데이트는 일반 종료와 같은 종료 조정 잠금을 사용해 메모와 설정 저장을 기다린 뒤 진행합니다.

## 기술 선택과 트레이드오프

- **Tauri와 Rust 백엔드:** Vue 기반 UI를 유지하면서 로컬 데이터와 운영체제 기능의 경계를 Rust가 소유합니다. 플랫폼 기능과 비동기 상태를 명시적으로 다룰 수 있는 대신 프론트엔드·Rust 양쪽의 타입과 이벤트 계약을 함께 관리해야 합니다.
- **Rust 커맨드 단일 데이터 경로:** 읽기와 쓰기를 모두 같은 경계로 보내 트랜잭션과 타입 계약을 한곳에 모았습니다. 화면별 간단한 조회도 커맨드를 추가해야 하지만, 프론트에 SQL과 데이터 규칙이 흩어지지 않습니다.
- **창별 Pinia와 이벤트 버스:** 각 웹뷰의 독립성을 유지하고 쓰기 성공 이벤트로 동기화합니다. 전역 메모리를 공유할 수 없기 때문에 이벤트 유실이나 재조회 시점을 고려한 복구 경로가 필요합니다.
- **OS를 자동 실행 상태의 단일 출처로 사용:** 앱 내부 사본과 실제 시작 프로그램 상태가 어긋나는 문제를 피합니다. 대신 설정 화면을 열 때 운영체제 상태를 다시 확인해야 합니다.
- **동의 기반 시스템 활동:** 컴패니언이 작업 맥락에 반응할 수 있지만, 기본 비활성과 최소 신호 원칙으로 기능 범위를 제한합니다. 더 세밀한 맥락보다 개인정보 보호와 로컬 처리를 우선한 선택입니다.
- **Rust가 소유하는 반복 일정 계산:** 창과 보기가 달라도 같은 반복 결과를 보여주고 시간대·서머타임 규칙을 한곳에서 검증합니다. 대신 화면에서 즉시 계산할 수 없어 조회 커맨드를 거쳐야 하고, 조회 범위를 366일과 결과 10,000회로 제한했습니다. 첫 버전에서는 Google 로그인과 동기화, 알림·공유·ICS를 제외해 로컬 일정 관리만으로 동작하도록 범위를 좁혔습니다.
- **사용자가 결정하는 업데이트:** 확인은 자동이지만 다운로드와 설치 시점은 사용자가 고릅니다. 새 버전 적용이 늦어질 수 있는 대신, 작업 중 앱이 임의로 재시작되거나 저장하지 않은 입력이 사라지는 상황을 막습니다.
- **랜딩 정적 자산으로 시작한 배포:** 별도 배포 인프라 없이 Cloudflare Workers 무료 범위에서 설치 파일과 업데이트 피드를 제공합니다. 파일 크기 한계나 앱 독립 배포가 필요해지면 저장소를 옮겨야 하지만, 확인 주소는 그대로 유지하도록 계약을 고정했습니다.

## 테스트·배포·운영 안정성

프론트엔드 테스트는 Vitest와 happy-dom을 사용하며 컴포넌트, Pinia 스토어, 기능별 composable·service, 창 배치와 컴패니언 상태·애니메이션 규칙을 다룹니다. Rust에는 순수 상태 결정, SQLx 인메모리 데이터베이스와 마이그레이션, 메모·캘린더·타이머·집중 규칙, 반복 일정과 시간대 전개, 시스템 활동 전이와 창·트레이 흐름을 검증하는 단위 테스트가 포함되어 있습니다.

배포는 Windows x64 NSIS 설치 파일로 하고 공식 사이트에서 직접 내려받습니다. 공개 이력은 2026년 9월 7일 첫 데모 배포(0.5.0-beta.1)와 자동 업데이트를 포함한 0.5.0-beta.2, 2026년 9월 21일 캘린더를 추가한 0.6.0-beta.1입니다. 업데이트 아티팩트는 서명과 체크섬을 함께 배포하고 설치 전에 검증하지만, 설치 파일 자체에는 아직 코드 서명이 없어 Windows 보호 경고가 표시될 수 있다는 안내를 랜딩에 두었습니다. 현재 Windows 전용이며 macOS 지원은 이후 계획입니다.

랜딩 페이지의 다운로드 요청은 Cloudflare D1에 날짜·버전별 횟수만 원자적으로 기록합니다. 개인 식별자, IP, 쿠키, User-Agent는 저장하지 않으며 재시도와 반복 다운로드가 포함될 수 있어 고유 사용자 수로 다루지 않습니다. 집계 저장이 실패해도 파일 응답은 계속 제공하고 실패는 로그로만 남깁니다. 빌드 단계에서 설치 파일·체크섬·업데이트 피드·서명의 불일치를 차단해 부분적으로 어긋난 릴리스가 공개되지 않도록 했습니다.

현재 Windows에서 유휴 상태 CPU 사용률 0.5% 이하, 기능 사용 중 3% 이하와 메모리 사용량 200MB 이하를 유지합니다.

주요 안정성 장치는 다음과 같습니다.

- 앱 종료 전에 편집 중인 메모를 저장하고 실패한 창이 있으면 종료를 취소하는 조정 흐름
- 집중 상태를 백그라운드에서 확인하고 종료·재시작 시 남은 시간을 일관되게 정리하는 supervisor
- 기능 창의 중복 생성 방지와 준비 완료 후 표시
- SQLite 마이그레이션, 외래 키 제약과 다중 테이블 트랜잭션
- 창별로 필요한 네이티브 권한만 나눈 Tauri capability 구성
- 일정 수정의 revision 충돌 감지와 논리 삭제·일회성 토큰 기반 실행 취소
- 창 닫기·앱 종료·업데이트 준비에서 저장하지 않은 일정 편집을 보호하는 확인 흐름
- 설치 직전 업데이트 피드 재확인과 버전·URL·서명 불일치 시 설치 중단

## 의사결정과 결과

### 문제

메모 기능을 블록별 도구로 명확하게 나누면서도, 사용자가 여러 블록을 한꺼번에 선택하고 복사할 때 흐름이 끊기지 않는 UI·UX가 필요했습니다.

### 대안 소개

- 각 기능이 명확히 분리된 독립 블록 중심 편집 방식
- 여러 블록이 하나의 긴 문서처럼 이어지는 통합 메모 방식

### 결정 이유

Notion을 비롯해 많은 사용자에게 익숙한 블록 기반 디자인을 유지하되, 문서 전체는 하나의 연속된 흐름으로 다루는 방식을 선택했습니다. 블록별 기능과 구조는 유지하면서도 드래그로 여러 블록의 텍스트를 연속 선택하고 복사할 수 있어야 했기 때문입니다.

### 결과

사용자는 개별 블록을 하나씩 선택하지 않고 여러 블록을 한 번의 연속된 드래그로 선택·복사할 수 있습니다.
